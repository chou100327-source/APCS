## 線性搜尋（Linear Search）

從頭到尾一個一個檢查，**不要求資料先排序**，時間複雜度 O(n)。

```python
def linear_search(a, target):
    for i in range(len(a)):
        if a[i] == target:
            return i     # 回傳索引
    return -1            # 找不到

print(linear_search([4, 2, 9, 6], 9))   # 2
print(linear_search([4, 2, 9, 6], 5))   # -1
```

## 二分搜尋（Binary Search）

**前提：資料必須已經排序好。** 每次比較中間值，把搜尋範圍砍半，時間複雜度 O(log n)，比線性搜尋快很多。這是觀念題與實作題都很愛考的主題。

```python
def binary_search(a, target):
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == target:
            return mid
        elif a[mid] < target:
            lo = mid + 1     # 目標比中間大，往右半找
        else:
            hi = mid - 1     # 目標比中間小，往左半找
    return -1

a = [1, 3, 5, 7, 9, 11, 13]
print(binary_search(a, 7))    # 3
print(binary_search(a, 4))    # -1
```

[[viz:binary]]

> **手動模擬二分搜尋（觀念題必練）**
>
> 陣列 `[1,3,5,7,9,11,13]` 找 **7**：第一輪 lo=0, hi=6, mid=3，`a[3]=7` 命中，直接回傳 3。
>
> 找 **4**：第一輪 mid=3，`a[3]=7 > 4`，hi 變 2；第二輪 lo=0, hi=2, mid=1，`a[1]=3 < 4`，lo 變 2；第三輪 lo=2, hi=2, mid=2，`a[2]=5 > 4`，hi 變 1；此時 lo > hi，迴圈結束回傳 -1。

## 兩者比較

| 比較項目 | 線性搜尋 | 二分搜尋 |
|---|---|---|
| 資料要先排序嗎 | 不用 | **一定要** |
| 時間複雜度 | O(n) | O(log n) |
| 1000 筆資料最多比較次數 | 1000 | 約 10 |

## 五分鐘小練習

```quiz
Q: 使用二分搜尋的前提是什麼？
* 資料必須已經排序
- 資料必須全為正整數
- 資料不能重複
- 資料量要夠小
E: 二分搜尋靠「跟中間值比大小來決定往哪半邊找」，沒排序就沒有方向性，結果會錯。

Q: 1000 筆已排序資料用二分搜尋，最多大約要比較幾次？
* 約 10 次
- 約 100 次
- 1000 次
- 500 次
E: 每次砍半，2¹⁰ = 1024，所以約 log₂1000 ≈ 10 次就能收斂。線性搜尋最差要比 1000 次。

Q: 二分搜尋中 `mid = (lo + hi) // 2` 算出中點後，若 `a[mid] < target` 該怎麼做？
* lo = mid + 1（往右半邊找）
- hi = mid - 1
- 直接回傳 mid
- lo = mid
E: 中間值比目標小，代表目標一定在右半邊，而 mid 本身已經比對過可以排除，所以 lo 移到 mid + 1。

Q: 線性搜尋找不到目標時通常回傳什麼？
* -1
- 0
- None 會噴錯
- 陣列長度
E: 回傳 -1 是慣例，因為 -1 不是合法索引，呼叫端很容易判斷「沒找到」。
```

## 常見錯誤

- **忘了先排序就用二分搜尋**：結果會時對時錯，超難除錯。
- **`while lo <= hi` 寫成 `<`**：會漏掉最後一個候選元素。
- **`lo = mid` 而不是 `mid + 1`**：範圍沒縮小會無窮迴圈。
- **回傳值搞混**：題目要「索引」還是「排名（1-based）」要看清楚，兩者差 1。
